# PCクイック登録の数字キー

PCの幅801px以上・マウス等の精密ポインターがある画面では、クイック入力に小さな番号を表示します。番号と同じ数字キーで既存ボタンをクリックします。テンキーも使用できます。0は10番目です。

- 現行の「選手 → スタッツ → 詳細」の順序を維持します。
- 表示中かつ有効な選択肢を画面順に採番し、余枠には変更・戻る等の補助ボタンを採番します。
- スタッツ画面はOUTまで10個。シュートは種類が最大5個、被ファウル・Made/Missを加えて8個です。
- 出場5人が確定しない試合は選手一覧が10個を超える場合があります。先頭10個を番号対応にし、残りは従来のクリック／タップで選びます。選手順・ページ構造は変更しません。
- コート座標は従来どおり直接クリック／タップします。被ファウルは既存チェックボックスのclickを呼びます。
- Escは既存の「戻る」を実行します。初期画面の取消操作（1つ戻す）には割り当てません。
- input・textarea・select・contenteditable等の操作中、IME変換中、修飾キー併用、長押し、非アクティブ時は数字キーを実行しません。
- 通常入力、履歴編集、交代の時間・選手フォームは対象外です。
- スマホ表示では番号表示・数字キー処理を無効にします。

実装は `quick-keyboard.js` から既存コントロールの `click()` を呼ぶだけです。Firestore、オフラインキュー、操作ID、履歴、AST連携、集計、コート計算に新しい登録経路を追加しません。

## 検証

- `node --test tests/*.test.mjs`（PowerShellではファイル一覧を展開）：99テスト成功。
- `node tests/quick-keyboard.browser.mjs`：PlaywrightとEdgeを使用。Playwrightが外部配置の場合はNODE_PATHを設定。ブラウザーはR32_BROWSER_CHANNELで変更可能。
- ブラウザー検証は実際の画面関数を読み込み、保存アダプターとコート描画を隔離した架空データで実行します。クリック・数字・テンキーの保存引数一致、各スタッツ、SHOT/Made/Miss/AST、FT、Esc、フォーム、長押し、非表示・disabled、10個超、オフライン時の同一アダプター呼出、スマホ幅とタッチを確認します。
- 実際の保存層のリトライ・再同期・ASTリンクは既存のstoreテストで別途検証します。本番への試験データ書込みは行いません。
- iPhone実機では未検証です。Edgeのモバイル／タッチエミュレーションで操作とボタン寸法不変を確認します。
- 全体テストで以前から残っていたSDKキャッシュの文字列検査を、現行のgstaticホスト分岐に合わせました。同期実装自体は変更していません。
